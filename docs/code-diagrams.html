02Class diagram: import engine

This diagram shows the five design patterns. Strategy: ImportStrategy and its three classes. Template Method: AbstractImportStrategy.run() calls the abstract doImport(). Factory: BookReaderFactory. Iterator: BookReader and BookRecord. Facade: BookImportService. It is drawn in two parts.

    +close() void

    -JdbcTemplate jdbcTemplate
    +insert(List~Book~) void
  }

    <<record>>
    long imported
    long skipped
    long durationMs

  class BookReader {
    <<interface>>
  }

  AbstractImportStrategy <|-- VirtualThreadsImportStrategy

The path of POST /api/books/import/excel?strategy=virtual-threads through the code. CSV works the same way with CsvBookReader.

sequenceDiagram
  autonumber
  actor C as Client
  participant S as Security filter
  participant X as ExcelImportController
  participant F as BookImportService
  participant G as BulkOperationGuard
  participant J as ImportJob
  participant V as VirtualThreadsImportStrategy
  participant R as ExcelBookReader
  participant W as BookBatchWriter
  participant D as MySQL

  C->>S: POST /api/books/import/excel (file, Bearer JWT)
  alt token missing or invalid
    S-->>C: 401
  end
  S->>X: importExcel(file, "virtual-threads", false)
  X->>F: importNow(file, XLSX, "virtual-threads")
  alt unknown strategy, empty file or not .xlsx
    F-->>C: 400 (via GlobalExceptionHandler)
  end
  F->>G: acquire()
  alt another bulk job is running
    G-->>C: 429 BulkOperationInProgressException
  end
  G-->>F: Permit
  F->>F: transferTo(temp file)
  F->>J: new ImportJob(file, format, permit)
  F->>V: run(job)
  V->>J: openReader()
  J->>R: BookReaderFactory.open(XLSX, path)
  loop until next() returns null
    V->>R: next()
    R-->>V: BookRecord
    Note over V: every 5000 records: start a virtual thread<br/>(max 20 at once, reader waits when full)
    par each batch thread
      V->>V: record.toBook() for 5000 records
      V->>W: insert(batch)
      W->>D: INSERT ... (one transaction)
    end
  end
  V->>V: wait for all batches
  V-->>F: ImportResult(imported, skipped, ms)
  F->>J: close()
  J->>G: Permit.close()
  Note over J: temp file deleted
  F-->>X: ImportResult
  X-->>C: 200 "XLSX import completed ... N books imported"

05Sequence: background import

With async=true, or the *-parallel-fire-and-forget endpoints, the request returns 202 as soon as the file is saved. The background thread owns the job and closes it at the end, even when the import fails.

sequenceDiagram
  autonumber
  actor C as Client
  participant X as CsvImportController
  participant F as BookImportService
  participant G as BulkOperationGuard
  participant J as ImportJob
  participant T as Background virtual thread
  participant V as ImportStrategy
  participant D as MySQL

  C->>X: POST /api/books/import/csv?async=true
  X->>F: importInBackground(file, CSV, "virtual-threads")
  F->>G: acquire()
  G-->>F: Permit
  F->>J: new ImportJob(temp file, permit)
  F->>T: Thread.ofVirtual().start(...)
  F-->>X: return
  X-->>C: 202 "CSV import accepted"
  Note over C,X: the client is free now

  T->>V: run(job)
  V->>D: batches of 5000 rows
  alt success
    V-->>T: ImportResult (logged)
  else failure
    V-->>T: exception (logged, not sent to the client)
  end
  T->>J: close()
  J->>G: Permit.close()
  Note over J,G: temp file deleted, next import may start

06Flow: virtual-threads pipeline

This is the inside of VirtualThreadsImportStrategy.doImport(). A semaphore with 20 permits limits the batches in flight. When all 20 are busy the reader waits (backpressure), which keeps memory and database connections bounded. After the first failure, reading stops.

flowchart TD
  start([doImport]) --> read[reader.next]
  read --> eof{record is null?}
  eof -- no --> add[add record to chunk]
  add --> full{chunk has 5000?}
  full -- no --> failed{a batch failed?}
  failed -- no --> read
  failed -- yes --> stop[stop reading]
  full -- yes --> permit{writers.tryAcquire}
  permit -- "no: all 20 busy" --> wait[wait for a free writer]
  wait --> launch
  permit -- yes --> launch[start virtual thread<br/>import-batch-N]
  launch --> failed
  eof -- yes --> last{partial chunk left?}
  last -- yes --> launch2[start last batch thread]
  last -- no --> drain
  launch2 --> drain[writers.acquire 20<br/>wait for all batches]
  stop --> drain
  drain --> ok{any failure?}
  ok -- no --> done([return ImportCounts])
  ok -- yes --> err([throw IllegalStateException<br/>committed batches stay])

  subgraph thread [each batch thread]
    direction TB
    p1[record.toBook x 5000<br/>count invalid as skipped] --> p2[BookBatchWriter.insert<br/>one transaction]
    p2 --> p3[writers.release]
    p2 -. exception .-> p4[record failure] --> p3
  end
  launch -.-> p1
  launch2 -.-> p1
