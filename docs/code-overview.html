Books API Handbook

A Spring Boot REST service that stores books in MySQL and loads them in bulk from CSV and Excel files. It compares several ways to import large files, and Keycloak protects every data endpoint.

00What the service does

  • Book CRUD: list (100 per page), read, create and delete books. A book has a title, an author and a price.
  • Bulk import from .csv or .xlsx files of up to 200 MB, with three processing strategies, either during the request or in the background.
  • Random data: insert up to 1,000,000 random books directly, or download a random CSV or Excel file to test the import with.
  • Protection: only one bulk job runs at a time (others get 429), and at most 20 database writers run at once, so normal requests still get a connection.

Single-row CRUD goes through Spring Data JPA. Bulk inserts skip Hibernate and go through BookBatchWriter, which calls JdbcTemplate.batchUpdate. Hibernate cannot batch inserts when ids come from MySQL AUTO_INCREMENT. With rewriteBatchedStatements=true, the MySQL driver sends each batch as a few multi-row INSERT statements.

02How an import runs

This is the path of POST /api/books/import/excel?strategy=virtual-threads. CSV takes the same path with a different reader.

  1. The controller fixes the format, XLSX or CSV, so an Excel endpoint never reads a CSV file.ExcelImportController → AbstractImportController.runImport()
  2. The facade checks the strategy name, rejects empty files and checks the file extension. Any problem returns 400.BookImportService.importNow() → prepare()
  3. It takes the single bulk-operation permit. If another import or generation is running, the answer is 429.BulkOperationGuard.acquire()
  4. The upload is moved to a temp file. Tomcat renames the file instead of copying it. The temp file and the permit are wrapped in one ImportJob.MultipartFile.transferTo() → new ImportJob(...)
  5. The strategy runs its fixed steps: open a reader, import, measure the time, log the result and close the reader.AbstractImportStrategy.run() → doImport(reader)
  6. The reader returns records one at a time. Each 5000-record batch is parsed and inserted on its own virtual thread, with at most 20 batches in flight.BookReaderFactory → ExcelBookReader.next() · VirtualThreadsImportStrategy.submitBatch()
  7. Each batch is one transaction of 5000 rows.BookBatchWriter.insert() · JdbcTemplate.batchUpdate()
  8. Closing the job deletes the temp file and releases the permit, even when the import fails.ImportJob.close()

With async=true, steps 1–4 run in the request, which then returns 202. Steps 5–8 run on a background virtual thread that owns the job and closes it at the end.

03Design patterns

Every strategy works with every format, and each part can change without touching the others.

PatternWhereWhat it gives
StrategyImportStrategy + 3 classesEach import method is a small class. Spring injects them all, and the facade finds one by its name().
Template MethodAbstractImportStrategy.run()The shared steps (open, time, log, close) are written once. Subclasses only write doImport().
FactoryBookReaderFactoryChooses CsvBookReader or ExcelBookReader for an ImportFormat.
IteratorBookReader.next(), BookRecordStrategies read format-free records one by one. CSV records are parsed later, on worker threads.
FacadeBookImportServiceOne entry point that hides validation, locking, temp files and threading.

To add a strategy, create a new @Component that extends AbstractImportStrategy. Spring picks it up automatically. To add a format, add an ImportFormat constant, a BookReader class and one case in BookReaderFactory.

04Import strategies

NameHow it worksMemoryLog tag
traditionalOne thread reads, parses and inserts batches in turn. This is the baseline.Bounded–
virtual-threadsA streaming pipeline with one virtual thread per 5000-record batch and at most 20 in flight. When all 20 are busy, reading waits. The first failure stops reading.Bounded (≤ 20 batches)[vt]
parallel-streamReads every record, parses them with parallelStream() in its own ForkJoinPool, then inserts batches one at a time.Whole file[ps]
backgroundAny strategy with async=true. The old fire-and-forget endpoints use virtual-threads.As the strategy[bg]

Measured time for 100,000 rows

For 1M CSV rows, earlier tests showed that MySQL insert speed is the limit, at about 640,000 rows per second. Changing the batch size (2000–10,000) or the writer count (10–28) made no real difference. In parallel-stream, parsing takes about 5% of the time and the one-at-a-time inserts take the other 95%.

05File formats

Both formats use three columns in this order: title, author, price. The same rules apply to both: a record is valid when the title and author are not empty and the price is a number. Invalid records, such as a header row, are skipped and counted. Blank lines and rows are ignored.

08Security

  • The app only checks tokens; it never logs users in. It has no client secret and no sessions. Get a token from Keycloak (realm books-realm, client books-service) and send it as Authorization: Bearer ….
  • Roles come from both realm_access.roles and resource_access.<client>.roles, upper-cased and prefixed with ROLE_.
  • /api/books/** needs USER or ADMIN. /api/admin/** needs ADMIN. Everything else needs a token, except the public paths: /, /health, /info, /api/health, /api/public/**, /actuator/health, Swagger and /error.
  • Token check: the signature uses Keycloak's key set (JWK), and the issuer must be http://localhost:8180/realms/books-realm. In Docker the key set is fetched from http://keycloak:8080/….

12Open issues

  • BlockerLogin does not work. Keycloak rejects user / user123, and the admin user from keycloak_setup.sh does not exist. No token means no access to the API, including through Postman and the test scripts.
  • HighDocker runs older code. Rebuild with docker compose up --build -d to get the Excel endpoints and the sample downloads.
  • MediumCPU setting mismatch. Compose limits the app to cpus: 4.0, but JAVA_TOOL_OPTIONS says -XX:ActiveProcessorCount=14. The JVM then sizes its thread pools, including the parallel-stream pool, for 14 cores it doesn't have. Set both to the same number.
  • MediumNo version control. The project is not a git repository, so changes cannot be reviewed or rolled back.
  • MediumProd schema. Prod uses ddl-auto: validate, but nothing creates the schema. db/migration/V1__add_price_column.sql never runs because Flyway is not a dependency.
  • LowDevelopment secrets in files. The database and Keycloak passwords, and the client secret used by the test scripts, are written in plain text in docker-compose.yml and *.sh.
  • LowKeycloak 23 is from 2023. Upgrading means setting up the realm again.
  • LowDocumentation sprawl. The project root has 92 Markdown files from earlier work, many of them out of date. AGENTS.md is current.
